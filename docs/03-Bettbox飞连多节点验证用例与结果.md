## 取证规则与边界

设备实测至少保留构建 run/SHA、脱敏后的状态截图、最终配置中的节点与组名、请求路由链及网络切换时间线。不得保存或上传授权文件、完整日志、Cookie、OTP、设备 ID、密码和私钥。当前 Wi‑Fi 本身可访问 ChatGPT，也可访问福州内网探针站点；两个站点的 HTTP 200、页面打开或飞连页“有响应”均不是隧道证据。必须对应到同一次请求的 WG 路由链与双向流量，或在隔离本地内网的网络上做可复现对照。

当前状态：`7c8a76b` 已在真实账号模拟器验证专属测速、双节点路由、单节点断链恢复、节点地址变化、真实授权空 Profile 和订阅刷新。临时配置、脚本、监听端口、转发及阻断规则均已撤销，原订阅恢复，模拟器已关闭。真机仍为旧包，新包的真机测速、独立故障、切网路径与浏览器访问尚未完成。四个企业后缀和内网 IP 默认规则、DNS 失败关闭及长期后台稳态仍是待办。

### 下发内网 DNS 的 DoH 探测（真机，2026-09-30）

请求历史已确认飞连会话下发的两台内网 DNS 的 UDP 53 流量经 `Fuzhou-Node-1-WG`，至少一次有双向字节；TCP 53 也经该节点发起。为检查是否可以改用加密的内网 DNS，曾临时给两台 DNS 地址各加一条精确 `/32` 福州规则，经手机混合代理发送标准 RFC 8484 HTTPS DNS 查询。两台都未完成 TLS 握手，关闭证书校验后仍超时；但失败连接没有进入可见请求历史。鉴于手机 Wi‑Fi 本身处于公司内网，不能证明这次 HTTPS 请求实际经福州 WG，也不能据此判断下发 DNS 是否支持 DoH。本次 DoH 能力探测判为**未完成**。飞连下发信息没有提供 DoH 主机名或证书校验参数；在得到可验证的 DoH URL、且确认测试流量走 WG 之前，不自动切换。现有内网 DNS 仍使用福州 WG 内的 UDP/TCP 53。

临时覆写已从手机应用及下载目录清除，原 `CorpLinkMultiNode` 恢复选中。恢复后经手机代理访问福州内网 HTTPS 与 ChatGPT trace 均返回 200；这些状态码只证明目标可达，不单独证明出口。Wi‑Fi、蜂窝开关、亮屏设置与 ADB 转发已恢复原状。

同日安装代理页测速修复提交 `8a84d85` 的 APK（[Actions run 36659207131](https://github.com/luantu/Bettbox/actions/runs/36659207131)，SHA-256 `d60213fb9a6f2f42b01f10d815fe92b8580adcf7dacde40adc6bad09bcaa678f`；包名与 v2 签名沿用原测试包）。保留数据安装成功，首页刷新为 `2/2`；但福州 WG 卡片点击测速仍显示 `Timeout`，此项判为**未通过**。同版本飞连页“检查连接”在 10:38 对福州私有 HTTPS 和 INTL ChatGPT 探针均报“有响应”，福州业务经手机混合代理为 HTTP 200；由于 Wi‑Fi 可直达目标，这两个响应只能作为对照，不能说明流量走 WG。后续必须记录代理页实际选用的 URL、核心返回值及对应请求的出口，再修复并重装复测。
