## 取证规则与边界

设备实测至少保留构建 run/SHA、脱敏后的状态截图、最终配置中的节点与组名、请求路由链及网络切换时间线。不得保存或上传授权文件、完整日志、Cookie、OTP、设备 ID、密码和私钥。当前 Wi‑Fi 本身可访问 ChatGPT，因此 M07 必须有内核请求链或受控反证；页面打开不是隧道证据。

当前状态：构建完成，空配置的失败关闭路径和最终包覆盖安装已有模拟器证据；真实飞连授权、双隧道传流、脚本命中、DNS 与真机切网均未通过验收。

## 模拟器预检（非最终候选版）

2026-09-29 以 Actions run `36551851735`、提交 `969aec8` 的 APK 做保留数据安装；本地文件 SHA-256 为 `acde8b45acf2bc9e9bf44f10f3fe5b09a95f98bb1b389205123369827224c87b`。该包早于单节点故障隔离修订，不能用于最终连通性判定。`BettboxSGApi35Test2` 模拟器能够启动应用，首页显示 SG-Node 磁贴，点击后能看到“飞连 VPN 节点”设置页和节点选择控件。该 AVD 内没有可用于本次授权的账号，未建立飞连隧道，因此 M02–M09 仍为待验证。

模拟器使用外置盘 AVD、单虚拟 CPU。软件 GPU 模式启动和 Flutter 页面加载时一度超过 400% 主机 CPU；改为宿主 GPU 并将进程优先级降至 20 后，界面清晰、页面可操作，占用约一个主机核心。预检结束已正常关闭模拟器。后续仍需控制运行时间，若负载再次过高，应停止而不是在后台持续运行。

## 空配置与最终包安装复核

专用空白 AVD `BettboxSGApi35Empty20260929` 创建后先确认没有 Bettbox 包，再安装提交 `7aa1959` 的安全候选 APK。只填写假的测试用户名、密码和不可达的本地 HTTPS 地址，同时选中 `FZ-INT-Node` 与 `FUZHOU-NODE-1`。授权明确失败，页面显示 `0/2`；运行配置中两个服务器同名组与 `SG-OpenAI` 均指向 `REJECT`，隐藏 `SG-Node` 只指向 INTL 组，两个 WireGuard 代理均未生成。系统 VPN 授权后，Android 网络服务报告由 Bettbox 持有的 VPN `tun0` 已连接。配置证据表明飞连目标没有可直连成员；本次未发起受控访问，不能据此宣称实际数据包路径或企业服务器登录成功。开启 VPN 后，单核模拟器的截图命令多次超时，首页状态曾短暂滞后，因此没有将首页实时性判为通过。模拟器已关闭。

最终候选 APK `e7295e8` 已在另一个外置盘 AVD `BettboxSGApi35Test2` 以保留数据方式覆盖安装成功，首页磁贴和飞连设置页可打开。该 AVD 没有本次可用的飞连账号，未进行真实隧道测试；其系统组件在单核启动阶段连续出现无响应弹窗，测试后已关闭。此环境问题不归因于 Bettbox，也不能用它解释真实设备结果。

安装包静态检查：包名为 `com.appshub.bettbox.sg`，最低 API 26，目标 API 36，包含 arm64 的 `libmeta.so` 与 `libcorplink-rs-login.so`。APK 的 v2 签名验证通过，证书 SHA-256 为 `ab1599095a426cb450a456f8f57158c10626032b44f362ff22fb86c02229b27c`，与此前同包名测试 APK 一致；这解释了模拟器上可以保留数据覆盖安装，但不等于真机凭据迁移已经验证。
