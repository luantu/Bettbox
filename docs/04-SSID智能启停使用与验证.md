# SSID 智能启停使用与验证

智能启停新增地点规则，用 Wi-Fi 名称区分使用相同私网网段的不同地点。升级保留旧 IP 规则、订阅、飞连授权与分流设置。新规则不改变 TUN 排除网段或代理规则。

## 配置方式

进入“更多 → 增强工具 → 智能启停”，打开开关后添加地点规则。使用“使用当前 Wi-Fi”可以填入当前 SSID；编辑框有独立的“保存规则”按钮，不需要登录或发现飞连节点。

- 只填 SSID：连接该名称的 Wi-Fi 后暂停。
- 同时填写 SSID 和 IP／网关：两个条件都满足才暂停，地址必须属于同一条底层连接。
- 只填地址：保留按地址识别的方式，不区分同网段的不同地点。

不同地点规则任一命中就暂停。SSID 精确匹配，区分大小写，名称中的中文、逗号和空格不会被拆开。地址列表用英文逗号分隔，最多五条；`192.168.110.0/24` 表示网段，`192.168.110.0/32` 只表示一个地址。网关条件示例为 `gateway:192.168.110.1`。

旧版 IP 规则在原字段中保留，继续独立生效，页面会显示提醒。要解决同网段误判，先建立对应地点规则，再由用户清空不再需要的旧规则。仅新增 SSID 规则不会取消旧 IP 规则。

## 权限和启停行为

读取当前 Wi-Fi 名称需要相应位置权限与系统定位开关。点击“允许读取 Wi-Fi 名称”后由系统弹窗授权；仅授予近似位置不能代替精确位置。Android 10 及以上退到后台后，本实现要求位置权限为“始终允许”，否则会报告不可读并保持状态。应用不扫描周边 Wi-Fi，也不向公共日志写入原始 SSID。

权限不足或切网期间读取失败时，状态显示不可读并保持当前启停状态，不将“SSID＋地址”降级为仅地址匹配。明确切到其他 Wi-Fi 或蜂窝后重新判断。SSID 和网段不是网络安全认证，不能防止他人伪装同名同网段网络。

Android 由后台服务统一执行启停，前台保存配置后请求检查。网络事件防抖一秒，后台每十五秒补偿检查；设置页同时显示底层网络、当前启停状态及判定原因。删除最后一条规则或关闭智能启停会释放本功能的暂停。手动停止及雅迪兼容暂停仍优先，不会被智能启停自动启动。

当 VPN 已是应用默认网络时，只采用系统继承的唯一物理传输类型和唯一对应网络识别出口。若系统没有提供足够证据或有多条候选连接，显示“当前底层出口尚未确定”，不按“Wi-Fi 优先”猜测。普通自动恢复与雅迪恢复使用不同准入；暂停后产生的新代次会撤销排队中的旧启动请求。

## 最终构建与设备结果

代码候选 `89f8661eb5d32257f726960f708f4b521186a21d` 的 [Actions run 39941835213](https://github.com/luantu/Bettbox/actions/runs/39941835213) 全链成功，耗时 14 分 59 秒。早期 SSID 专项 26 项通过，后续模型生成一致性、Flutter 分片、原生恢复策略、内核、登录 helper 及 APK 打包均通过。可下载 [arm64 APK 构建产物](https://github.com/luantu/Bettbox/actions/runs/39941835213/artifacts/12497441012)。

包名为 `com.appshub.bettbox.sg`，版本为 `1.19.7 (2026101601)`。APK SHA-256 为 `7f67907927807044a06374e83dcf3746ca565baca806ebbf2d56c6ec1a32501a`；固定 v2 签名证书 SHA-256 为 `ab1599095a426cb450a456f8f57158c10626032b44f362ff22fb86c02229b27c`。包含 `libmeta.so`、`libcore.so`、`libcorplink-rs-login.so`、`libcode_forge.so` 四个 arm64 库。手机已同签名保留数据安装，从手机读回的 `base.apk` 哈希与上述产物一致。

外置盘单核 API 35 模拟器验证使用最终云端 APK，不以早期本地重签包代替。实际保存首条规则后，配置文件和卡片均有规则；相同 SSID 命中后 `tun0` 消失。改成其他 SSID 后 `tun0` 重建；同名 SSID 加错误网段不会暂停，改成实际网段则暂停。切到模拟蜂窝时，即使 IPv4 同属一个 /24 网段，也会恢复 TUN；切回 Wi-Fi 后重新暂停。关闭系统定位时保留暂停状态。手动停止后经过网络变化、超过十五秒补偿周期及强停重开，TUN 没有自行启动。升级前后的安装时间与 Profile 身份摘要一致。

真机 API 37 通过系统界面授予精确位置和“始终允许”。新增当前 Wi-Fi 规则后，临时清空旧 IP 条件，页面明确显示“命中地点规则”，TUN 不存在。两轮 Wi-Fi／蜂窝往返中，应用退到后台后，离开 Wi-Fi 自动重建 TUN，回到该 Wi-Fi 自动暂停。第一次蜂窝启动后短暂显示出口尚未确定；当时保持运行，未按猜测切换状态。两节点随后显示 `2/2`；手动重新启动后的代理页实测为 INT 组 210 ms、福州组 41 ms。这是节点专属探针结果，不把直连 Wi-Fi 的页面访问当作隧道证据。

真机首页手动停止后，Wi-Fi 开关、后台静置及重新打开应用没有触发自启动。测试结束删除临时地点规则、逐字恢复原旧版网段条件和总开关，回到原来的智能暂停；Wi-Fi 开、蜂窝数据关、熄屏时间一分钟及原常亮选项均已恢复。账号、节点、订阅及覆写脚本没有编辑。精确位置／后台权限保留供正式使用。测试期间未出现本次列表保存、监听派发异常或未处理 Flutter 异常。

智能暂停期间仍观察到既有 WG 的 `CorpLink native transport not ready` 提示；当时 TUN 已按规则关闭，不能把这条暂停状态下的提示当成“运行中恢复失败”。本轮不声称已消除该提示。雅迪前台、长时间锁屏、跨地点同名热点和真实基站漫游没有重做，不能以短时切网替代这些验证。

旧 IP 条件按用户要求完整保留，仍会独立命中。需要避免同网段误暂停时，应为实际地点建立 SSID 规则，确认后再删除对应旧 IP 条件；程序不会擅自迁移或清空它们。
