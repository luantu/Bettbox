# Bettbox 飞连独立配置与自恢复设计

本设计以当前 `codex/feilian-android` 分支为基线。目标是让飞连连接拥有独立入口和明确状态，并在无机场配置、订阅变更和隧道异常时保持可预期行为。最终是否可用，仍以 Android 上的登录、握手、DNS 和 ChatGPT 实测为准。

## 当前断点

1. `patchRawConfig` 在没有活动 Profile 时返回空配置；因此即使飞连账号已保存，Mihomo 也无配置可启动。
2. `applyCorplinkSgNode` 在没有本地认证文件时直接退出；界面无法展示待授权的代理组，也没有稳定的配置合并边界。
3. 飞连设置藏在“内核配置 → 常规”的对话框中，登录成功、等待、失败和隧道健康没有独立状态页面。
4. WireGuard 已有网络切换重连和业务失败后的连接失效，但没有独立于业务流量的定期探测；长时间空闲后的半开连接可能要等用户访问才暴露。
5. 已有订阅更新会重新应用活动 Profile；但飞连目前依赖认证成功后的临时注入，没有对“无配置 → 订阅配置”这个迁移过程定义清楚。

## 设计

### 飞连配置与状态

在“更多”页面增加直接可见的“飞连 SG-Node”入口。独立页面负责保存三项凭据、显示启用状态、最近一次授权/探测结果，并提供“重新授权”和“检查连接”动作。设置保存、授权和应用配置分开执行；失败时保留原普通代理的可用性，错误只显示脱敏的阶段和代码。

飞连使用单一状态序列：未配置、待授权、授权中、已授权、隧道正常、隧道异常、需要重新登录。状态来自真实的 helper 事件和 Mihomo 节点探测，不从 `tun0` 是否存在推断。

### 配置合并

飞连配置是覆盖层，不修改下载的 YAML。每次最终配置构建均执行一次幂等合并：

- 已授权：生成 `SG-Node` WireGuard-TCP 出站和 `SG-OpenAI` 组，将节点加入用户已有的 OpenAI/ChatGPT 组；按开关插入 OpenAI 规则。
- 未授权：保留 `SG-OpenAI` 组作为明确的待连接入口，但不生成虚假的 WireGuard 节点。OpenAI 默认阻断，防止意外直连；用户选择机场回退时才使用机场组。
- 用户订阅中的其他节点、组和规则保持原顺序；合并重试不产生重复 SG 节点、组和规则。

当没有活动 Profile 且飞连已启用时，应用创建一个仅含基础 `DIRECT` 组和 `MATCH` 规则的本地引导 Profile。它用于启动 Mihomo 和承载飞连覆盖层。用户后来导入或下载真实 Profile 后，自动切换到真实 Profile；引导 Profile 不参与订阅更新，也不覆盖其内容。

### 恢复

飞连启用且核心运行时，每隔一段时间通过核心对 `SG-Node` 做一次独立延迟探测。连续失败达到阈值后进入冷却，先请求内核重连 TCP/WireGuard；如果控制面明确报告 Cookie 失效，再执行重新授权。恢复操作串行化，按指数退避，网络未就绪时不形成循环。手动“检查连接”可以立即探测，但不能绕过并发锁。

内核仍保留已有的网络变化重连和业务失败恢复。自动探测只负责发现空闲故障并驱动现有恢复路径，不在 UI 中另建 WireGuard 实现。

### 安全和验收

密码、Cookie、OTP 和私钥仅写入现有受保护位置。日志不得包含原始服务器响应、认证 URL 或敏感字段。状态页面只展示阶段、时间和安全错误码。

验收必须覆盖：无 Profile 启动、导入/更新订阅后的幂等合并、授权失败时普通代理不受影响、节点故障退避和恢复，以及 Android 上的真实 TCP WireGuard 握手、隧道 DoH 和 ChatGPT 连通。
