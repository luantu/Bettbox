# SG-Node 真机网络切换与首页磁贴设计

本修订解决两个已确认的缺口：蜂窝切回 Wi-Fi 后，网络变化回调过早重连，旧飞连 TCP 连接仍留在蜂窝地址，真机约 143 秒后才自动恢复；首页缺少可直接观察和恢复 SG-Node 的入口。

## 行为与边界

1. 物理网络切换事件合并处理：从最后一次事件起等待短暂稳定窗口，再执行一次已有的 WireGuard transport 重连。连续到来的事件只触发最后一次计划；服务停止后不得执行迟到的重连。不修改用户名、Cookie、WireGuard 密钥，也不在网络抖动时强制重新登录。若重连仍失败，既有健康检查继续负责有界的完整重建。
2. SG-Node 首页磁贴只在 Android 上出现，首次升级默认加入已有首页布局，排在启动按钮之前。加入记录只执行一次；用户之后从首页编辑中删除、重新添加或排序时，配置必须保留。按真机反馈，磁贴采用与“网络检测”等小卡片一致的半宽、高度随内容计算的布局：标题及刷新按钮在上，关键连接状态在下；隧道 IP 和详细检查结果留在飞连页，避免狭窄磁贴截断。刷新按钮直接触发与飞连页相同的按状态恢复；点磁贴主体进入飞连配置页。不得展示凭据、Cookie、OTP、设备 ID 或私钥。
3. 飞连页与磁贴共享恢复决策，避免同一状态在两个入口触发不同动作。正常状态仅做业务探测；首次握手等待、transport 未就绪和需要完整重建分别采取现有对应动作。自动恢复与人工刷新都必须在操作后重新读取核心状态。

## 实现顺序与验证

- 先写网络事件合并/取消的测试，再修改服务侧重连调度；以真机两方向切换验证，不用模拟器成功替代真机。
- 再写首页布局一次性迁移、磁贴配置序列化及共享恢复决策测试，然后实现磁贴和飞连页复用。
- GitHub Actions 全链编译同签名独立包；真机保留数据覆盖安装，验证首页磁贴默认可见、可删除和重新添加、刷新后状态更新。
- 真机在 Wi-Fi→蜂窝及蜂窝→Wi-Fi 各重复至少两轮；从物理网络可用到经 SG 的 ChatGPT 测试地址首次 HTTP 200，目标约 30 秒。记录活跃飞连 TCP 的物理来源、隧道 IP 和握手状态；Chrome 在“规则”模式下的请求须显示 `SG-OpenAI → SG-Node`。测试完成恢复用户原有“全局”模式与设备临时设置。

未登录的 ChatGPT 页面、网站单次测速或相同的公网出口 IP 都不单独构成“走 SG 隧道”的证明。验证须结合 Android VPN、请求路由及受控数据面访问。
