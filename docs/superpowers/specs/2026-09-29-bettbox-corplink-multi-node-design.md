# Bettbox 飞连多节点独立隧道设计

本设计以 `v1.19.4-sg.1` 的源码为基线。目标是在同一份 Mihomo 配置中同时使用上游返回的多个 TCP VPN 服务器：账号登录一次，每个服务器各有 WireGuard 密钥、VPN 会话、TCP 隧道、连接状态和恢复动作。用户用覆写脚本把流量分给各服务器的代理组；ChatGPT 自动规则直接指向已勾选的 INTL 组。

## 决策与边界

采用“共享账号认证、节点级隧道”的方案。单个 WireGuard 实例挂多个 peer 无法独立维护 CorpLink 分配的 IP 和会话；为每个节点重复密码登录则违背单次登录要求。这两种做法都不采用。

这次只新增 TCP 节点（上游 `protocol_mode=1`）。UDP 节点不出现在可选列表中。设置页允许用户手动补充服务器原名，以应对列表暂不可用，但不能把手填名称当作服务器已确认存在。当前已知目标是原 INTL 节点和 `FUZHOU-NODE-1`；具体名称以控制面返回及用户选中的字符串为准。

新节点不自动加入机场组，也不生成福州域名或 `RULE-SET` 规则。应用不再生成 `SG-OpenAI` 和 `SG-Node` 兼容组；勾选并成功授权 INTL 时，原 ChatGPT 域名规则直接指向该服务器同名组，否则不生成这些自动规则。机场原有对象与规则保持不变。此次不改变公开测试签名，也不把账号、Cookie、OTP、设备身份或私钥写进仓库、日志和状态接口。已发布的 `v1.19.4-sg.1` 不受开发过程影响。

## 名称与配置模型

一个选中的服务器保存为 `CorplinkNodeSelection`：`serverName`、`enabled` 和可空的 `healthUrl`。`serverName` 是从列表选中或用户手填的准确名称，也是脚本可引用的代理组名。选择后的名称保持稳定；若上游后来改名，界面提示重新选择，不静默重命名代理组和用户脚本。

| 对象 | 命名规则 | 用途 |
|---|---|---|
| 代理组 | `<serverName>` | 覆写脚本的规则目标，例如 `FUZHOU-NODE-1` |
| WireGuard 代理 | `<serverName>-WG` | 该组内唯一的真实飞连出站 |

Mihomo 不允许代理和组同名，因此 `-WG` 后缀不可省略。应用在合并配置前检查服务器名是否为空、重复、看起来是 URL 或包含规则分隔符，或与机场已有代理／组冲突；不覆盖用户配置。只有已勾选且可授权的节点才生成同名组与 `-WG` 出站。未勾选或无授权的节点不生成代理、组或 `REJECT` 占位。若脚本仍引用缺失节点，相关规则及依赖组改指 Mihomo 内置的 `REJECT`，依赖该节点拨号的代理移除并提示；这不创建新的 `REJECT` 代理或组。不能简单删除保护规则，让域名落入后续 `MATCH,DIRECT`。

现有安装首次升级时保留账号设置、引导 Profile、机场订阅和脚本。用户勾选真实 INTL 名称后，应用从现有授权文件迁移密钥；未勾选时不沿用旧 `SG-Node` 代理。列表不可达时显示旧设置但不凭历史名称生成节点，也不强制重新登录。新增服务器各生成并持久化自己的 WireGuard 密钥对。新密钥按账号、上游地址及服务器名隔离，存于平台安全存储；现有 helper 私有授权文件保持兼容。普通偏好设置只保存节点名称和启用状态；健康探针 URL 可能暴露内部主机，按节点存入平台安全存储，不写入日志或仓库。

## 发现、授权与建连

Rust helper 继续只负责一次账号登录并保存 CookieStore、OTP 材料和稳定设备身份。应用增加只读的 TCP 服务器列表调用，复用内核现有的控制面请求与 Android 受保护底层网络；返回设置页的只有服务器名称和协议模式，不返回 Cookie、令牌或密钥。列表失败时显示上次选择并允许手动补充，不伪报节点可用，也不触发第二次登录。

每个启用的服务器对应独立 `WireGuard` 出站。它使用共享登录 Cookie 和 OTP 材料，但以自己的公钥执行 `/api/vpn/list → /vpn/ping → /vpn/conn`；`vpn-token`、选定端点、分配的隧道 IP、虚拟 IP 栈及 TCP Bind 仅保存在该实例中。管理请求和外层 TCP 仍使用 Android `VpnService.protect`。INTL 的远端 DNS 保持隧道内 DoH；福州内网域名按增量设计使用服务端下发、只经福州隧道的 DNS，不回退手机本地解析器。详见 [[2026-09-29-bettbox-corplink-node-dns-design]]。

同一账号会话是否允许两个不同公钥同时连接，必须在真机上实测。若服务端拒绝并存，报告具体的脱敏错误与受影响节点；不得偷偷为第二节点再次登录或伪造“已连接”。

## 最终配置与脚本

应用仍把飞连配置当作覆盖层，不修改下载的订阅 YAML。第一次合并让脚本看到已勾选服务器的同名组；脚本执行后再次做幂等核对，确保每个可用节点的 `-WG` 代理和同名组各只有一份。脚本加入的 `rule-providers` 保留，指向仍可用节点的 `RULE-SET` 保留；指向未勾选节点的规则改指 Mihomo 内置 `REJECT` 并提示，不能因删除规则而落入后续直连。

ChatGPT 的内置规则只在 INTL 已勾选并可用时生成，目标直接为该服务器原名组；不保留旧 `SG-OpenAI` 或 `SG-Node` 生成对象。新增服务器组不自动取得福州流量。用户可在覆写脚本中写 `RULE-SET,<provider>,Fuzhou-Node-1`；取消勾选后该规则改指内置 `REJECT` 并提示，不能留下悬空目标或直连回退。无机场的引导 Profile 与订阅更新后重合并沿用既有流程，实际勾选的组必须保持幂等。

## 独立状态与恢复

核心提供按服务器名称索引的只读状态列表，并保留旧单节点状态接口供迁移期调用。新接口只含节点名、初始化／握手／重建阶段、脱敏错误码、隧道 IP 和当前端点；不含账号或授权材料。手动动作按名称重连或重建一个节点。首页现有 SG 磁贴改为一张“飞连节点”汇总卡，显示就绪数与启用数，例如“2/2 已连接”；进入飞连页后可逐节点检查、刷新和重连。汇总卡的刷新只处理异常节点，不因一个探针失败让所有隧道重建。

每个节点可独立设置一个 HTTPS 健康检测地址。地址必须使用 HTTPS，不接受 URL 内嵌的用户名、密码或片段。留空时只报告 TCP/WireGuard 握手就绪，业务连通标为“未检测”，不能以 ChatGPT 或其他公网地址的失败判定该节点故障。设置了探针时，对该节点使用独立的连续失败计数、冷却和恢复锁；单次站点失败不触发重连。

Android 物理网络变化时通知所有启用的飞连 TCP Bind，但每个实例独立重连。`/vpn/conn` 如分配了新的隧道 IP，内核只关闭并重建受影响节点的虚拟 IP 栈；其他节点的现有连接和选择状态不变。当前全量 `applyProfile()` 恢复路径不能用作节点级重建的静默替代。若实现层无法安全地局部重建，应将这一点作为阻断项修正或重新评审设计，而非声称节点互相独立。

## 错误与安全边界

服务器列表缺失、非 TCP、单节点握手失败或探针失败只影响对应节点。共享登录确实失效时才发起一次串行的账号重新授权；其他节点已有的健康数据面不因某个节点的普通业务错误而立即失效。错误页和日志只输出阶段与数值代码，不回显服务端原文、Cookie、OTP、公私钥或登录 URL。当前控制面 TLS 验证关闭的问题不因多节点功能而扩大为新的明文或日志路径；它仍需单独安全修订，测试 APK 不能当作生产发行版。

## 验收门槛

自动化测试必须覆盖：节点列表只保留 TCP、URL 误填被拒并从旧保存记录中过滤、密钥隔离、两个勾选节点配置幂等、未勾选时没有组和占位代理、脚本有效 `RULE-SET` 保留、失效引用改指内置 `REJECT` 防止落入直连、名称冲突不覆盖机场、单节点失效不影响另一个、按名称重连／局部重建及汇总磁贴。Go 测试模拟同一个登录会话下两个不同公钥的 `/vpn/conn`，确认控制面令牌、端点和隧道 IP 不串用。Flutter 测试确认 ChatGPT 自动规则直指已勾选 INTL，未勾选 INTL 时不生成。所有相关测试及 GitHub Actions Android arm64 APK 构建都要通过。

先在外置磁盘上的 Android arm64 模拟器安装 CI APK。真实授权保留在 `BettboxSGApi35Fresh` AVD，空配置测试使用 `BettboxSGApi35Empty20260929`；一次只启动一个模拟器，单核运行，测试后关闭，不在 Mac 内置磁盘另装系统镜像。模拟器要验证设置页的服务器列表多选、URL 误填清理、空 Profile、只有勾选节点入配置、脚本 `RULE-SET` 命中与失效规则失败关闭、逐节点状态及刷新。已有真实账号的 AVD 须验证两条真实隧道与业务；需要用户再次输入密码时使用可见窗口。不能拿空白 AVD 的假服务结果冒充真实企业 VPN。

模拟器验证结束后，输出 `docs/03-Bettbox飞连多节点验证用例与结果.md`。每个用例包含环境与构建提交、前提、操作、预期、实际结果、脱敏证据、通过／失败／未验证状态；失败用例保留并注明修复后重测结果。模拟器结果先写入，再以真机记录补全同一文件。截图和日志只临时放在 `work/corplink-multi-node/`，不提交账号、上游 URL／IP、Cookie、OTP、设备 ID 或私钥。

真机验收以同时在线为准：一次账号登录后两个服务器组与两条真实 WG 出站同时存在；各自的健康探针或受控目标取得响应，请求历史能分别显示对应服务器原名组与 `-WG` 节点。只让一条隧道断开时，另一条连续请求不得中断；故障节点的手动刷新和自动恢复都要成功。Wi-Fi／蜂窝双向切换后，两条隧道分别恢复，记录 IP 是否变化。ChatGPT 通过直接指向 INTL 组的自动规则连通，原机场代理和订阅更新不受影响。规则模式下至少一条由覆写脚本注入、仅指向 `Fuzhou-Node-1` 的域名规则必须实际命中，且域名 DNS 经其 WireGuard 出站。真机实测全部通过并复核验证文件后，才能宣称多节点功能闭环。

本设计通过后先在独立开发分支实施和验证，不直接修改已发布标签或自动发布新 Release。编译成功只证明产物可安装，不能代替上述真机验收。
