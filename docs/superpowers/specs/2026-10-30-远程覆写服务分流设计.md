# 远程覆写服务分流设计

复用 Bettbox 的 JavaScript 覆写和 Mihomo HTTP rule-provider，独立部署到既有规则服务器。账号、SG 出站和同名组仍由应用管理；脚本保留这些对象，添加 OpenAI 和 Google fallback 组。用户已授权完善方案并直接实施。

## 选点与规则

OpenAI 按 INT、支持地区的订阅叶节点排序；Google 按韩国、其他支持地区的订阅叶节点、INT 排序。同层保留订阅顺序，失败则切换下一个健康候选。仅承认可识别且在支持清单内的地区名称，排除香港、澳门、中国大陆、俄罗斯、未知或多地区冲突名称，以及 DIRECT、REJECT、企业 WG、信息条目。支持 proxy-provider 的同等过滤，未识别节点不纳入。名称仅用于筛选，实际出口与服务支持仍以测试为准。

两个组各自使用服务相关HTTPS探针，静态节点健康检查每60秒、超时5秒；动态provider沿用其检查周期，不承诺覆盖既有周期。检查失败后新连接选择下个健康候选，不保证原请求自动重试。不以403声称业务解锁。缓存规则每日更新，发布包从同份根目录规则生成首启应急快照。无订阅时两个组各含INT；无任何候选时明确报错，动态provider过滤为空用内置REJECT避免直连，不创建占位节点。

覆写脚本命名为 `overwrite-bettbox.js`，从 172.18.34.110:44468 下载。直接复用根目录 `padavan_openai_domains.yaml`、`google_proxy_domains.yaml`、`sg-node-overseas-no-google.yaml`，不新增重复规则文件、不修改现有规则来源。OpenAI优先于Google，再于海外通用。原企业域名、服务器下发IP和本机绕过规则随远程脚本保留，发布时从旧脚本导出，不纳入公开仓库。服务器本身的单IP直连规则解决下载引导依赖。原订阅节点、组、规则和非托管providers保留，重复执行不增长。脚本不内嵌机场节点地址、密码、密钥或固定订阅节点名单；只引用上游及飞连已有对象。

DNS 为服务域名使用显式绑定对应组的 DoH；企业 DNS 继续使用福州 WG 已实现的隧道内解析。应用既有自动 OpenAI 分流关闭，避免它在脚本后重新插入直指 INT 的规则。两份 Profile 均启用同一全局脚本。智能启停最终恢复原状。

选择脚本方案是因为本次需求属于分流策略与规则托管；替代方案为把国家和域名逻辑编入 APP，但会使规则更新依赖 APK；单纯修改订阅则无法覆盖无订阅情况。

## 验收

行为测试覆盖空配置、订阅筛选/排序、禁用 INT、provider 过滤、同名冲突、幂等、保留原配置、DNS 与下载引导。Mihomo 真实解析与 HTTP provider 加载通过。手机分别激活本地 SG 与订阅 Profile，核对分组、来源、规则和真实连接链；至少让 ChatGPT、Google 请求分别命中对应规则与出站，不能用 Wi-Fi 直连成功代替证据。临时诊断端口与调试设置结束恢复。
