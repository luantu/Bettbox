# Bettbox 飞连独立配置实施计划

目标：实现独立设置页、无订阅引导配置、订阅更新后幂等合并，以及有退避的 SG 隧道恢复。

架构：飞连授权仍由 `corplink-rs` helper 完成，Mihomo-SG 负责 WireGuard-TCP；Bettbox 只管理设置、Profile 覆盖层和健康探测。下载的订阅文件不被改写。

技术：Flutter/Dart、Go/Mihomo、GitHub Actions Android arm64。

设计依据：[[2026-09-28-Bettbox-飞连独立配置与自恢复设计]]。

## 约束

- 凭据、Cookie、OTP、私钥不进日志或 Git。
- 现有机场节点和用户分流保持原顺序。
- 无真实 Android 握手证据时不宣称最终可用。
- 本机不安装大型 Flutter/NDK；使用 GitHub Actions 构建测试。

## 工作包

### 1. 配置合并

- [ ] 写失败测试：无认证时创建 SG 组；认证后创建节点和组；重复合并不重复；订阅已有组/规则保持顺序。
- [ ] 将覆盖层提取为可测试的纯函数，配置构建前后使用相同函数。
- [ ] 在 CI 中执行 Dart 单元测试。

### 2. 无订阅引导与订阅迁移

- [ ] 写失败测试：首次启用且无 Profile 时选中引导 Profile；添加首个真实 Profile 后切换。
- [ ] 创建固定 ID 的本地引导 Profile，并在启动和设置保存时检查。
- [ ] 对当前 Profile 的下载更新继续调用现有 `applyProfileDebounce`，由最终配置层合并 SG。

### 3. 独立页面与状态

- [ ] 在“更多”中增加直接入口，显示设置、授权结果、节点探测结果和重试操作。
- [ ] 显示脱敏错误码；保存设置后分别执行授权与配置应用。

### 4. 恢复

- [ ] 写失败测试：连续探测失败才重连；成功清零；退避阻止重连风暴。
- [ ] 在核心运行期间定期探测 SG 节点，调用已有 `reconnectTunnels` 桥接；Cookie 明确过期时重新授权。
- [ ] Android 实测关闭/恢复网络后重新探测。

### 5. 构建与验收

- [ ] 运行 Dart/Go 测试和 Android Actions 构建。
- [ ] 在外置盘模拟器安装最新 APK，验证独立页面、无 Profile 和订阅迁移。
- [ ] 记录登录、握手、DoH、ChatGPT 的实测结果；没有证据的项目保持未完成状态。
